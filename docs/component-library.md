# 元件库精度规范（设计决策）

> 状态：**已实现并全部对拍**（2026-10-26）—— 14 个型号进 Rust 库、MNA 装配器已在用，
> 界面层也已消费这些器件（削波指示用二极管电流）。
> **BJT 的动态档（C1 结电容 + C2 渡越时间）已补**（2026-10-27，E82）：`ft` 与 ngspice 差 < 5%；
> 锗管的扩散电荷（`Tf=600ns` ⇒ 41 nF）因求解器限制暂未启用，见 §8。
> 相关：`DEVLOG.md` E31 / ADR-012；`README.md` 的「仓库结构」
> 下一步输入：用户将提供 LTspice 风格的器件模型，按本文的档位与参数字段导入。

---

## 0. 两条先决结论（会改变所有取舍）

### 0.1 元件精度**不影响延迟**

插件延迟固定为 **15 个样本**，由过采样 FIR 决定（`Engine::latency_samples()`）。
元件加多少参数都不改变这个数值。所以"平衡性能与延迟"实际是**平衡 CPU 与保真度**。

### 0.2 精度的成本结构分两类，量级差别很大

| 类别 | 典型参数 | 在 MNA 里的代价 |
|---|---|---|
| **非线性静态项** | `Is, Bf, Vaf, Ikf, Ise/Ne, Isc/Nc, Vto, Beta, Lambda` | 每次牛顿迭代多几个 `exp` / 除法；**成本随「器件数 × 迭代次数」增长** |
| **线性动态项** | `Cje, Cjc, Cj, Cgd, Cgs, Tf, Tr` | 只增加矩阵非零元 + 一个历史电流源；**不增加未知量**，成本 +5~10% |

> 早期曾估计"BJT 结电容 +30~40%"，那是按"每个电容一个未知量"算的，**错误**。
> 电容是线性的，不增加牛顿维度。

**真正的 CPU 驱动因素是：非线性节点数 × 牛顿迭代次数**，而不是参数个数。

## 1. 精度档位定义（两条轴）

早期用过的 `L1/L2/L3` 把静态与动态混在一起了，不好用。改用两条独立的轴：

### 静态 I-V

| 档 | 包含 | 适用 |
|---|---|---|
| **D1** | `Is, N` | 只在极小信号/教学场景 |
| **D2** | + `Rs`（体电阻，软化拐点） | 硅二极管、MOSFET 体二极管 |
| **D3** | + 高注入 / 漏电 / Early：`Bf, Vaf, Ikf, Ise/Ne, Isc/Nc`（BJT）/ `Lambda`（JFET/MOS） | **所有做放大或有漏电的器件** |

### 动态（结电容）

| 档 | 包含 | 适用 |
|---|---|---|
| **C0** | 无 | 低频削波、反馈环内小电流场景（**默认**） |
| **C1** | + `Cj`（结电容） | 大结电容（1N4007、MOSFET）、高阻节点 |
| **C2** | + 扩散电容 / 恢复（`Tf, Tr, tt`） | 高频、开关、反向恢复相关 |

> 换算：原 L1 ≈ **D2+C0**、L2 ≈ **D3+C0**、L3 ≈ **D3+C2**。

### 2.2 Sparklin Drive 实际用到的精度

| 器件 | 实现 | 差距 |
|---|---|---|
| 1N4148 | **仅 `Is / N / Rs`**（D2+C0） | 缺 `Cjo=4p, M=.4, tt=20n` |
| OP07 | **仅 `A0 / GBW`** | 压摆率已算未启用；缺输出摆幅、共模、输入偏置 |

### 2.3 关键证据：省掉结电容是站得住的

Sparklin Drive 的二极管只用了 `Is/N/Rs`，而 ngspice 用的是含 `Cjo/tt` 的完整模型。
**活体对拍（`tests/oracle.rs`）：h2–h9 最大偏差 0.056 pp**（THD 27.648% vs 27.581%）。

→ 在 **1 kHz、反馈环内、二极管电流 ~10⁴ µA 量级** 的条件下，`Cjo=4p`、`tt=20n` **完全可忽略**。

**这条就是"先省、再测、超标才加"的样板。**

## 3. 逐器件推荐

| 器件 | 推荐档 | 必须给的参数 | 可以省 | 听觉机制（为什么是这个档） |
|---|---|---|---|---|
| **锗 BJT（NPN/PNP）** | **D3 + C2** | `Is, Bf(50~200), Vaf, Ise/Ne, Isc/Nc, Rbb', Cje/Cjc, Tf/Tr` | `Itf/Xtf` 高阶项 | **漏电决定整级工作点**（Fuzz Face 的偏置就靠它）；低 `Vf`(0.2~0.3V)、低 `Bf` 给出绒软压缩；温度极敏感（≈ −2 mV/°C） |
| **锗二极管** | **D2 + C0** | `Is(~10⁻⁶), N(1.5~2), Rs(10~100Ω)` | `Cj` | 0.3V 低拐点 + 大 `Rs` → **圆头削波**，"锗味"的全部来源 |
| **1N4007（硅整流）** | **D2 + C1** | `Is, N, Rs(较大), Cjo(20~30p)` | `tt`（先省） | 大芯片 ⇒ `Rs` 软化拐点；`Cjo` 比 1N4148 大 5~7 倍，在**高阻节点**（几百 kΩ 反馈）可能可闻 |
| **2N7000（MOSFET）** | **D2 + C1** | `Vto, Kp(or Beta), Lambda, 体二极管` | `Cgd/Cgs` 高阶项 | 踏板里基本只做削波/开关：跨导与体二极管是主角；结电容只在做高频增益级时才重要 |
| **BC549C（已有）** | **D3 + C2** | `Is, Bf, Vaf, Ikf, Ise/Ne, Cje/Cjc, Tf` | `Itf/Xtf` 的高阶项、`Cjcs` | 已补齐：`ft` 114 MHz vs ngspice 120 MHz（E82） |
| **J201（已有）** | **D3 + C0** | `Beta, Vto, Lambda` | `Cgs/Cgd` | `Vto/Lambda` 决定夹断软硬 |
| **OP07（已有）** | **宏模型 A（1 内部节点）** | `A0, GBW, **压摆率**, 输出摆幅` | 共模、噪声、失调 | **压摆率 0.25 V/µs 是 OP07 性格的核心**：大信号时高频压缩 |
| **1N4148（已有）** | **D2 + C0** | `Is, N, Rs` | `Cjo, M, tt` | 已验证可忽略（§2.3） |

### 一句话原则

> **静态精度给足（D3），动态精度按用途给（多数 C0，大结电容/高阻节点才 C1）。**
>
> 因为静态项决定"音色对不对"，而且它几乎不增加 CPU（多几个 `exp`）；
> 动态项只在特定拓扑/频段才可闻，却要额外承担数值刚度。

## 4. 为什么 `1N4007` 的 `tt` 可以先省

`tt=30 µs` 看起来吓人（1 kHz 周期 1000 µs，占 3%）。但是：

- `tt` 是**反向恢复**，只在"导通 → 截止"的瞬间起作用；
- 反馈环削波里二极管电流只有几十~几百 µA，恢复电荷极小；
- 而 `Cjo=20p` 是**始终存在**的，优先级更高。

→ 1N4007 先做 `D2+C1`，用 §5 的实验判定是否需要 `tt`。

## 5. 如何"用数据决定精度"

对每个器件跑两个对拍实验，全部用现成工具（`rustomp-oracle`）：

### 实验 1：静态 V-I 扫描

```
.dc V1 -2 2 0.01
```

- 验收：`D2`（精简）与完整模型在 `|I| > 1 µA` 区间**相对误差 < 2%**；
- 饱和区（高注入）误差 < 10%，或据此决定升 `D3`。

### 实验 2：真实拓扑下的谐波

同一电路（如 10k 串联 + 二极管对地削波），分别用「精简模型」与「完整模型」跑 1 kHz / 10 kHz 的 THD 与逐次谐波：

- 验收：h2–h9 偏差 **< 0.1 pp @1 kHz**；**< 0.3 pp @10 kHz**；
- 超了就升档（C0→C1→C2）。

> 这套流程已可用：`rustomp-import`（网表）+ `rustomp-oracle`（跑 ngspice + 同一套测量函数）。
> 精度决策因此是**可测量的工程判断**，不是争论。

### 5.1 M-C 闭环的实测（2026-10-27，DEVLOG E86）

设计器工程 → 生成的 `Ckt` → THD，和"同一张网表喂 ngspice"用**同一套测量函数**比：

| 电路 | 性质 | 我们的 `Ckt` | ngspice | 差 |
|---|---|---|---|---|
| `lowpass`（10k+100n） | 线性对照（守尺子） | 0.0000 % | 0.0000 % | 0 |
| `diode-clip`（1N4148 ∥ 1N34A） | 二极管硬削波 | 26.554 % | 26.554 % | −0.000 pp |
| `pretty-face`（AC127 ×2 法兹） | 锗管 + 反馈 + 削波 | 60.53 % | 60.93 % | −0.39 pp |

判据：非线性电路 < 2 pp、二极管纯电路 < 1 pp（测试里就是这么卡的）。
锗管剩下的 0.39 pp 来自未建模项（`Nk`、`Xcjc/Cjcs`、`Irb`），已在 §8 记档。

## 6. CPU 预算（按非线性节点数，不按参数数）

| 电路 | 非线性未知量 | 每样本估算 | 4x 过采样 · 48 kHz · 立体声 |
|---|---|---|---|
| 1 节点（现状 Sparklin Drive） | 1 | 206 ns | 7.8% |
| 2 只 BJT（差分/缓冲） | 3~4 | ~300 ns | ~11% |
| 3 只 BJT + 运放（典型 fuzz） | 6~8 | ~500 ns | ~20% |
| 上面全部加结电容 | 同左（线性项） | **+5~10%** | ~21~22% |

→ **给静态精度加参数几乎不花 CPU；加器件才花 CPU。**

## 7. 与总体路线的关系

器件库是「**闭集器件模型 + 通用 MNA 装配器**」路线（ADR-012）的第一层：

实际落地（`crates/rustomp-dsp/src/mna.rs`）：

```rust
/// 电路里的一个元件 = 型号 + 拓扑（节点号）。器件模型本身不知道拓扑。
pub enum Element {
    Diode  { model: Diode,  a, k },
    Bjt    { model: Bjt,    npn: bool, c, b, e },
    Jfet   { model: Jfet,   d, g, s },
    Mosfet { model: Nmos,   d, g, s },
    Resistor { a, b, r },
    Capacitor { a, b, c, v_prev },          // 后向欧拉伴随模型
    OpAmp  { model: OpAmpModel, state, p, m, out, branch, pin },
}

// 装配器：节点 0 = 地，其余为未知量；电压源各占一个支路未知量
let mut net = Netlist::<5>::new();
net.resistor(1, 2, 4_700.0)
   .bjt(BC549C, true, 2, 3, GND)
   .voltage_source(4, 1, GND, 9.0);
let v = net.solve_dc();
```

**关键取舍：器件只提供"端电压 → 流入器件的电流"，雅可比由装配器数值差分。**

```rust
// 例：BJT 的"电流函数"（PNP 就是把电压/电流取反）
sys.multiport(&[c, b, e], v, |vv| {
    let (ic, ib) = model.terminal(s * (vv[1] - vv[2]), s * (vv[1] - vv[0]));
    vec![s * ic, s * ib, -s * (ic + ib)]
});
```

- 好处：**加一个新器件只需写一个电流函数**，不可能出现矩阵/符号写错；
- 代价：每次牛顿迭代多算 `n+1` 次模型 —— 对 3 端器件可忽略（见 §6 预算）；
- 热点（BJT/二极管）将来可以换成解析雅可比，接口不变。

**求解器**：gmin 步进（`1e-3 → 0`，每级热启动）+ 阻尼牛顿 + 部分主元 LU。
运放 DC 用**连续极限**（增益 `A0`）装配，饱和时"钉"在摆幅上重解（分段线性迭代）；
瞬态用离散更新式 `v_out = a·v_out_prev + b·vd`（线性 → 直接进代数环）。

### 对拍结果（`tests/mna.rs`）

| 电路 | 量 | 与 ngspice 偏差 |
|---|---|---|
| 二极管削波（6 个 DC 点） | `v(out)` | **≤1.6 µV** |
| BJT 共射偏置（BC549C） | `v(b)`, `v(c)` | **≤123 µV** |
| JFET 共源（J201） | `v(d)` | **34 µV** |
| RC + 削波瞬态（48 kHz，240 点） | 波形 | **≤17 mV**（后向欧拉 vs 梯形） |
| 运放非反相 10× | DC 增益 / -3dB | 10.998 / 40.5 kHz（原型 54.5 kHz，见下） |
| **Sparklin Drive 整机**（`tests/sparklin_mna.rs`） | DC 工作点 / THD / 频响 | **0.056 mV / 27.579% vs 27.5682%（+0.011 pp）/ ≤0.5 dB** |

> 运放在 192 kHz 采样下 -3dB 点偏低约 26%（54.5 → 40.5 kHz）：离散化取舍，已记档。
> 近 Nyquist 的增益地板（`b/(2+bk)`）会被引擎的抽取滤波器滤掉，音频带内不受影响。

### 精度升级不能改"型号身份"

升级 `BC549C` 的参数集（例如从 D3+C0 升到 D3+C1）**不改变型号名**，
只改 `const` 里的字段与 `stamp()` 的实现；电路的网表/实例不变。

### 10.1 两个需要注意的问题

**① `2N7000` 用的是 LTspice 专有的 `VDMOS(...)` 模型，ngspice 不支持**

实测报错：

```
warning, can't find model '2n7000' from line
    m1 d g 0 0 2n7000
could not find a valid modelname
```

试过"近似转成 ngspice 的 MOS level 1"（`--vdmos-as-nmos1`）：
`Vto=1.6, Kp=.17, Rd=0, Rs=.75` → `Id@Vgs=5V,Vds=5V = 0.70 A`，
而真实 2N7000 在 `Vgs=5V` 大约只有 0.1~0.2 A —— **差 4 倍以上，不可接受**。
（LTspice 的 VDMOS 自带 triode 限制与 `Kp` 定义都与 level-1 不同。）

→ **需要**：一个 ngspice 兼容的 2N7000 模型（厂商 SPICE 库里的 `NMOS level=1/3` 或 `subckt`），
或者提供 VDMOS 的原始定义与允许的误差范围，我们手写等价的 subckt（体二极管 + Rds(on) 限制）。

**② `1N4007` 的结电容与恢复时间像是默认值**

模型里 `CJO=1e-11`（10 pF）、`TT=1e-7`（100 ns）；而 1N4007 数据手册典型值是
`Cj ≈ 15 pF`、`trr ≈ 30 µs`。若确实是通用默认值，高频行为会偏。

对削波用途影响有限（按 §3 仍是 `D2+C1`），但如果要建"整流管削波"的高频细节，建议换一个实测模型。

| `BC549C` / `AC127` / `AC128` / `BC559C`(PNP) | `devices::Bjt`（静态 **D3**：Gummel-Poon + `Rb/Re/Rc` + 大信号结电压限制；动态 **C1**：`Cje/Cjc`（含 `Fc` 线性化），硅管再开 **C2**：`Tf/Tr`） | **Ic 与 Ib 均对拍**：AC127/AC128/BC559C ≤0.01%，BC549C ≤0.09%（唯 Ic≈4.6 mA 处 0.67%，见下）；**直流工作点与 ngspice 一位不差**（锗管法兹，`tests/designer_generated_fuzz.rs`） |
| `1N5817`（肖特基） | `devices::Diode`（D2） | **0.00%**（1 µA~10 mA；Vf@1 mA=0.124 V、@10 mA=0.205 V） |

| 通用单运放 `OP07` | `devices::OpAmp`（单极点宏模型 + 压摆率 + 输出钳位） | 闭环 -3dB ≈ GBW/11（4× 过采样下误差 <2%）；单位增益跟随误差 <10 mV |

> 运放的两个离散化决定（E38）：
> 1. **不用显式欧拉**（闭环时间常数小于采样周期，必然发散）；
> 2. **不用梯形法**（Tustin 在 54 kHz 处把频率轴扭曲 +36%，运放会"变快"）。
>    用**精确极点离散** `v[n] = a·v[n−1] + b·vd[n]`（`a = e^{−ωp·dt}`），对 `vd` 线性 → MNA 可解进代数环。
> 3. 应在 **≥4× 过采样**下运行；基带 192 kHz 时 -3 dB 点会偏低约 30%（采样率限制，非模型误差）。

> 精度说明（BJT）：
> - 实现了 `Is/Bf/Nf/Vaf/Ikf/Ise/Ne/Br/Nr/Var/Ikr/Isc/Nc` 与 `Rb/Re/Rc`；
> - **未实现**：`Nk`（BC549C 的 `Nk=0.6339`）、`IRB/RBM`、结电容 `Cje/Cjc/Tf/Tr`（后者属 C1/C2 档）；
> - BC549C 在 `Ic≈4.6 mA` 处偏 +0.67%（其余 0.00~0.09%），推测与未建模的 `Nk` 有关，
>   远低于 5% 门槛，暂不处理 —— **不为拟合而猜模型语义**。
>
> **大信号处理（E81，2026-10-27）**：结电压越过 `vcrit = vt·ln(vt/(√2·Is))` 后，
> `exp` 改为**切线线性延续**（值与一阶导都连续）——与 SPICE 的 `pnjlim` 同一思路。
> 这不是优化，是**正确性前提**：把 `exp` 硬钉一个上限会把导数钉成 0，牛顿拿不到方向，
> 锗管（`Is=5µA` ⇒ `vcrit≈0.21 V`）的直流工作点会直接跑到 1e34 V。
> 硅管 `vcrit≈0.74 V`，正常工作电压全在指数区，模型**逐位不变**（现有一切对拍数字不受影响）。
>
> 极性约定：`Bjt` 是**极性无关**的（同一套 NPN 公式）。PNP 使用时把
> `(veb, vcb)` 传进去，并对返回电流取负 —— 与 SPICE 内部 `type = -1` 的处理一致（已对拍验证）。

> **动态档（E82，2026-10-27）**：结电荷 `Q(v) = ∫C dv`（`C = Cj(1−v/Vj)^−Mj`，
> `v ≥ Fc·Vj` 后按切线延续），扩散电荷 `Qf = Tf·Ict/Qb`（含 `Itf/Xtf` 滚降）、`Qr = Tr·|Ict|/Qb`；
> 位移电流 `i = (q − q_prev)/Δt` 用后向欧拉装配，**不增加未知量**。
> 验收（`tests/bjt_dynamics.rs`）：
>
> | 型号 | 我们的 `ft` | ngspice `ft` | 差 |
> |---|---|---|---|
> | BC549C（`Vbe=0.664 V`、`Vce=5 V`） | 114.2 MHz | 119.7 MHz | −4.6% |
> | AC127（`Vbe=0.15 V`、`Vce=8.2 V`，`Tf` 打开） | 0.244 MHz | 0.25 MHz | −2.4% |
>
> 直流工作点**逐位不变**（`dc` 时结电容开路）；运放+二极管电路逐样本相同（见 DEVLOG E82 审计）。
> **扩散电荷（C2）四个型号全开**（E85）：靠 SPICE 的 `pnjlim` 结电压限幅 + 解析雅可比 + 残差判据，
> 锗管 `Tf=600ns` 的 41 nF 扩散电容也能全拍收敛（残差 6e-11、最多 9 次迭代、24 µs/拍）。
>
> **热路径（E83）**：模型常量（`vcrit`/`ec`）在**建元件时预计算**（不再每次 `exp` 前做 `ln`），
> 电流与**解析雅可比**一次算齐（旧实现每次迭代调模型 7 次做数值差分）。
> 实测每拍 65 → **23.6 µs**（2.7×），`bjt_stage` 的波形差 1.9e-6（相对）、Sparklin 逐位不变。
> 端电压离谱时（`vbc>8 V`）自动退回"参考实现 + 数值差分"，把非物理区的行为钉在原样。

> 重要细节：热电压取 **27 °C（`VT=0.025865`）**，与 SPICE 默认 `TNOM` 对齐；
> 用 300 K 会带来约 −0.05% 的系统性偏差（实测发现并修正）。

### 10.2 运放：`models.add` 里**只有符号，没有模型**

文件中 `RC4558`、`TL072` 两段是 **LTspice 的符号定义**（`.asy` 内容：`SYMBOLTYPE`/`LINE`/`PIN`…），
真实模型指向**外部文件**：

```
SYMATTR SpiceModel ..\sym\EXTRA\AudioOpamp\TI\RC4558.301
SYMATTR SpiceModel ..\sym\EXTRA\AudioOpamp\TI\TL072.301
```

→ 需要提供 `.301` / `.lib` / `.subckt` 本体，否则无法做 oracle 对拍。
另外 `TL072` / `RC4558` 都是**双运放**，涉及"一个封装两个单元共用电源"的建模（见 §10.3）。

### 10.3 已确认的决策（2026-10-23）

| 项 | 结论 |
|---|---|
| 2N7000 | **手写**等价子电路（已完成并标定：`devices/handwritten.lib` 的 `N2N7000`） |
| 1N4007 | **用实测/数据手册模型**（`CJO=15p`、`TT=5µs`，DC 不变） |
| 运放 | **不做双运放、不导入新运放**；库内只维护**一个通用运放器件**，采用 CPU 友好精度（1 内部节点宏模型 + 压摆率 + 输出摆幅） |

> 依据：LTspice 的双运放一般也拆成单运放使用；breadspice 的双运放本来就是两个 OP07A 拼的。
> 因此 IR 与器件库都**不需要**"多单元器件"能力。
