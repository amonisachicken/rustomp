# 元件库精度规范（设计决策）

> 状态：**已定原则，待实现**（2026-10-23）
> 相关：`DEVLOG.md` E31 / ADR-012；`README.md` 的「仓库结构」
> 下一步输入：用户将提供 LTspice 风格的器件模型，按本文的档位与参数字段导入。

---

## 0. 两条先决结论（会改变所有取舍）

### 0.1 元件精度**不影响延迟**

插件延迟固定为 **15 个样本**，由过采样 FIR 决定（`Engine::latency_samples()`）。
元件加多少参数都不改变这个数值。所以"平衡性能与延迟"实际是**平衡 CPU 与保真度**。

### 0.2 精度的成本结构分两类，量级差别很大

| 类别 | 典型参数 | 在 MNA 里的代价 |
|---|---|---|
| **非线性静态项** | `Is, Bf, Vaf, Ikf, Ise/Ne, Isc/Nc, Vto, Beta, Lambda` | 每次牛顿迭代多几个 `exp` / 除法；**成本随「器件数 × 迭代次数」增长** |
| **线性动态项** | `Cje, Cjc, Cj, Cgd, Cgs, Tf, Tr` | 只增加矩阵非零元 + 一个历史电流源；**不增加未知量**，成本 +5~10% |

> 早期曾估计"BJT 结电容 +30~40%"，那是按"每个电容一个未知量"算的，**错误**。
> 电容是线性的，不增加牛顿维度。

**真正的 CPU 驱动因素是：非线性节点数 × 牛顿迭代次数**，而不是参数个数。

## 1. 精度档位定义（两条轴）

早期用过的 `L1/L2/L3` 把静态与动态混在一起了，不好用。改用两条独立的轴：

### 静态 I-V

| 档 | 包含 | 适用 |
|---|---|---|
| **D1** | `Is, N` | 只在极小信号/教学场景 |
| **D2** | + `Rs`（体电阻，软化拐点） | 硅二极管、MOSFET 体二极管 |
| **D3** | + 高注入 / 漏电 / Early：`Bf, Vaf, Ikf, Ise/Ne, Isc/Nc`（BJT）/ `Lambda`（JFET/MOS） | **所有做放大或有漏电的器件** |

### 动态（结电容）

| 档 | 包含 | 适用 |
|---|---|---|
| **C0** | 无 | 低频削波、反馈环内小电流场景（**默认**） |
| **C1** | + `Cj`（结电容） | 大结电容（1N4007、MOSFET）、高阻节点 |
| **C2** | + 扩散电容 / 恢复（`Tf, Tr, tt`） | 高频、开关、反向恢复相关 |

> 换算：原 L1 ≈ **D2+C0**、L2 ≈ **D3+C0**、L3 ≈ **D3+C2**。

## 2. 现状对照

### 2.1 breadspice `models.lib` 提供的精度（工业级 SPICE）

| 器件 | 参数 | 档位 |
|---|---|---|
| 1N4148 | `Is=2.52n Rs=.568 N=1.752 Cjo=4p M=.4 tt=20n` | D2 + C2 |
| 1N5817（肖特基） | `Is=31.7u Rs=.051 N=1.373 Cjo=190p M=.3` | D2 + C1 |
| LED 红/绿/蓝 | `Is=93.2p Rs=42m N=3.73/4.61/7.47 CJO=2.97p VJ=.75 M=.333 TT=4.32u` | D2 + C2 |
| BC549C / BC559C | `Is Bf Vaf Ikf/Nk Ise/Ne Br Isc/Nc Rc Cje/Cjc Tf/Tr Itf/Xtf` | **D3 + C2**（完整 Gummel-Poon） |
| J201 | `Beta Vto Lambda Rd Rs Is Cgd Cgs` | D3 + C1（完整 NJF） |
| OP07A | 30+ 元件的 `.SUBCKT` | 超出"单器件"范畴（见 §4.7） |
| 2N7000 | `Vto=1.6 Rd=.75 Rs=.14 Rb=.14 Kp=.17 Cgdmax=80p Cgdmin=12p Cgs=50p Cjo=50p Ron=2` | D3 + C1（完整 VDMOS） |

### 2.2 Sparklin Drive 实际用到的精度

| 器件 | 实现 | 差距 |
|---|---|---|
| 1N4148 | **仅 `Is / N / Rs`**（D2+C0） | 缺 `Cjo=4p, M=.4, tt=20n` |
| OP07 | **仅 `A0 / GBW`** | 压摆率已算未启用；缺输出摆幅、共模、输入偏置 |
| R / C | 理想元件 | 无 ESR、无介质吸收（DA） |
| 电位器 | 线性两段电阻 | 无 taper、无抽头电容 |

### 2.3 关键证据：省掉结电容是站得住的

Sparklin Drive 的二极管只用了 `Is/N/Rs`，而 ngspice 用的是含 `Cjo/tt` 的完整模型。
**活体对拍（`tests/oracle.rs`）：h2–h9 最大偏差 0.056 pp**（THD 27.648% vs 27.581%）。

→ 在 **1 kHz、反馈环内、二极管电流 ~10⁴ µA 量级** 的条件下，`Cjo=4p`、`tt=20n` **完全可忽略**。

**这条就是"先省、再测、超标才加"的样板。**

## 3. 逐器件推荐

| 器件 | 推荐档 | 必须给的参数 | 可以省 | 听觉机制（为什么是这个档） |
|---|---|---|---|---|
| **锗 BJT（NPN/PNP）** | **D3 + C0** | `Is, Bf(50~200), Vaf, Ise/Ne, Isc/Nc, Rbb'` | `Cje/Cjc/Tf` | **漏电决定整级工作点**（Fuzz Face 的偏置就靠它）；低 `Vf`(0.2~0.3V)、低 `Bf` 给出绒软压缩；温度极敏感（≈ −2 mV/°C） |
| **锗二极管** | **D2 + C0** | `Is(~10⁻⁶), N(1.5~2), Rs(10~100Ω)` | `Cj` | 0.3V 低拐点 + 大 `Rs` → **圆头削波**，"锗味"的全部来源 |
| **1N4007（硅整流）** | **D2 + C1** | `Is, N, Rs(较大), Cjo(20~30p)` | `tt`（先省） | 大芯片 ⇒ `Rs` 软化拐点；`Cjo` 比 1N4148 大 5~7 倍，在**高阻节点**（几百 kΩ 反馈）可能可闻 |
| **2N7000（MOSFET）** | **D2 + C1** | `Vto, Kp(or Beta), Lambda, 体二极管` | `Cgd/Cgs` 高阶项 | 踏板里基本只做削波/开关：跨导与体二极管是主角；结电容只在做高频增益级时才重要 |
| **BC549C（已有）** | **D3 + C0** | `Is, Bf, Vaf, Ikf, Ise/Ne` | `Cje/Cjc/Tf` | 扩到 D3 就够；升 C1 才需要电容 |
| **J201（已有）** | **D3 + C0** | `Beta, Vto, Lambda` | `Cgs/Cgd` | `Vto/Lambda` 决定夹断软硬 |
| **OP07（已有）** | **宏模型 A（1 内部节点）** | `A0, GBW, **压摆率**, 输出摆幅` | 共模、噪声、失调 | **压摆率 0.25 V/µs 是 OP07 性格的核心**：大信号时高频压缩 |
| **1N4148（已有）** | **D2 + C0** | `Is, N, Rs` | `Cjo, M, tt` | 已验证可忽略（§2.3） |

### 一句话原则

> **静态精度给足（D3），动态精度按用途给（多数 C0，大结电容/高阻节点才 C1）。**
>
> 因为静态项决定"音色对不对"，而且它几乎不增加 CPU（多几个 `exp`）；
> 动态项只在特定拓扑/频段才可闻，却要额外承担数值刚度。

## 4. 为什么 `1N4007` 的 `tt` 可以先省

`tt=30 µs` 看起来吓人（1 kHz 周期 1000 µs，占 3%）。但是：

- `tt` 是**反向恢复**，只在"导通 → 截止"的瞬间起作用；
- 反馈环削波里二极管电流只有几十~几百 µA，恢复电荷极小；
- 而 `Cjo=20p` 是**始终存在**的，优先级更高。

→ 1N4007 先做 `D2+C1`，用 §5 的实验判定是否需要 `tt`。

## 5. 如何"用数据决定精度"

对每个器件跑两个对拍实验，全部用现成工具（`rustomp-oracle`）：

### 实验 1：静态 V-I 扫描

```
.dc V1 -2 2 0.01
```

- 验收：`D2`（精简）与完整模型在 `|I| > 1 µA` 区间**相对误差 < 2%**；
- 饱和区（高注入）误差 < 10%，或据此决定升 `D3`。

### 实验 2：真实拓扑下的谐波

同一电路（如 10k 串联 + 二极管对地削波），分别用「精简模型」与「完整模型」跑 1 kHz / 10 kHz 的 THD 与逐次谐波：

- 验收：h2–h9 偏差 **< 0.1 pp @1 kHz**；**< 0.3 pp @10 kHz**；
- 超了就升档（C0→C1→C2）。

> 这套流程已可用：`rustomp-import`（网表）+ `rustomp-oracle`（跑 ngspice + 同一套测量函数）。
> 精度决策因此是**可测量的工程判断**，不是争论。

## 6. CPU 预算（按非线性节点数，不按参数数）

| 电路 | 非线性未知量 | 每样本估算 | 4x 过采样 · 48 kHz · 立体声 |
|---|---|---|---|
| 1 节点（现状 Sparklin Drive） | 1 | 206 ns | 7.8% |
| 2 只 BJT（差分/缓冲） | 3~4 | ~300 ns | ~11% |
| 3 只 BJT + 运放（典型 fuzz） | 6~8 | ~500 ns | ~20% |
| 上面全部加结电容 | 同左（线性项） | **+5~10%** | ~21~22% |

→ **给静态精度加参数几乎不花 CPU；加器件才花 CPU。**

## 7. 与总体路线的关系

器件库是「**闭集器件模型 + 通用 MNA 装配器**」路线（ADR-012）的第一层：

```rust
/// 器件只负责"给定端电压 → 注入各节点的电流 + 雅可比"，不含拓扑。
pub trait Device {
    const EXTRA_NODES: usize = 0;      // 运放 1，其余 0
    fn stamp(&self, v: &[f64], sys: &mut MnaSystem);
}

pub struct Bjt { is, bf, vaf, ikf, nk, ise, ne, br, isc, nc, rb, re, rc, .. }
pub const BC549C: Bjt = Bjt { is: 7.049e-15, bf: 493.2, vaf: 23.89, .. };
```

- **型号是闭集**：`BC549C` / `J201` / `OP07` / `1N4148` … 每个型号一个 `const`；
- **实例只描述拓扑**：`BjtInstance { model: &'static Bjt, nodes: (c, b, e) }`；
- 参数名与 SPICE 对齐（`Is/Bf/Vaf/...`），这样 LTspice 模型可以直接映射。

### 精度升级不能改"型号身份"

升级 `BC549C` 的参数集（例如从 D3+C0 升到 D3+C1）**不改变型号名**，
只改 `const` 里的字段与 `stamp()` 的实现；电路的网表/实例不变。
