# AB 测试复盘：Sparklin Drive v2（MNA 生成）vs legacy（手推 WDF）

> 时间：2026-10-25
> 参与者：用户（听感 / 信号源 / FFT 截图）+ 助手（指标 / 台架复现 / 修复）
> 相关记录：`DEVLOG.md` E49（首次全生成产物）、E50（次谐波 bug）、E51（电位器端点 bug）
> 一句话结论：**"听起来差不多"和"算对了"之间，隔着一次 AB 测试和两个真 bug。**

---

## 1. 为什么要做这次 AB

第 49 阶段第一次用**全生成链路**（网表 → 电路代码；toml → 插件外壳）产出了 Sparklin Drive v2。
它在数字上很好看：THD 27.65 %、h2–h9 与 ngspice 逐次差 ≤0.03 pp、直流工作点差 0.06 mV。

但这些都是**同一条实现**上的自证。真正的问题是：

> 换了一条完全不同的数值路径（通用 MNA + 定点迭代 vs 手推 WDF + 收敛判据），
> 声音还是同一台机器吗？

AB 测试就是回答这个问题的唯一办法 —— 而且必须**两个插件同时装进宿主**、参数对齐、盲听。

---

## 2. 装置与方法

| 项 | 做法 |
|---|---|
| 宿主 | Logic Pro，单声道音轨 |
| 两个身份 | `Sparklin Drive Mono`（Sp02，v2）/ `Sparklin Drive Legacy Mono`（SLm1，legacy） |
| 身份隔离 | legacy 仓库改成独立身份（AU `SPm1→SLm1`、VST3 id、CLAP id、名字加 Legacy），**不动 DSP** |
| 参数对齐 | Gain / Level 都放在同一点（默认 50%），映射都是 0..1 → 0..500k |
| 延迟对齐 | 两者都是 15 样本（同一个 `Engine`）→ 不会因梳状滤波产生"厚薄"错觉 |
| 客观测量 | 输入 **880 Hz / 1 kHz 正弦与方波**，用 Channel EQ 的 Analyzer 观察频谱 |
| 主观测量 | 真实吉他演奏（单音 / 和弦 / 重拨 / 轻拨） |

> 注：v2 当时**没有 GUI**（Logic 显示通用两推子），legacy 有完整面板 ——
> 这本身不影响听感，但要求操作时**手要稳**：设置不对等，AB 就白做了。

## 3. 时间线

### 3.1 第一轮：用户听出"数字味"

用户反馈（原话要点）：

> 音色取向相同，但**新版高频更毛更亮**，并且混入了一些难以察觉却导致整体音色劣化的
> **浑浊刺耳成分，有数字味**。

助手当时的**纯技术推演**（只凭指标）：

| 维度 | 预测 |
|---|---|
| 谐波结构 | **不可能**不同（同一器件模型、同一拓扑，h2–h9 ≤0.03 pp） |
| 低频 / 压缩曲线 / 直流呼吸 | **不可能**不同 |
| 高频 | 新版略亮 0.5–1 dB（运放离散化：精确极点 vs 梯形） |
| 瞬态 | 新版略"钝"（后向欧拉的数值阻尼 + 2 次迭代） |

**预测的方向对了一半，量级错得很远**（实际是 +2–4 dB 的高次谐波，外加一个 −0 dB 的次谐波）。

### 3.2 FFT 截图：正弦正常，方波露馅

用户接入信号源后的四张图（880 Hz）：

| 输入 | legacy | v2（当时 2 次迭代） |
|---|---|---|
| 正弦 | 干净的谐波阶梯 | 谐波阶梯**更密更高**（10–18 kHz 抬高） |
| **方波** | 干净、平滑 | **基频以下出现大片隆起 + 谐波间锯齿杂散** |

**基频以下的能量是关键证据**：那意味着输出已经不是"输入的周期信号"了 —— 这是数值伪影，不是电路的声音。

### 3.3 台架复现：定位到"次谐波极限环"

离线台架（880 Hz、Gain 50%、预热 2 s、取 0.2 s；dB 相对基频）：

| 实现 | f/2 | f/4 | f/8 | f/16 | 谐波阶梯 |
|---|---|---|---|---|---|
| legacy（WDF，收敛） | −80 | −86 | −70 | −83 | 平滑 |
| **v2 @2 次迭代** | **+1** | −2 | **+12** | **+19** | 锯齿（h6=+7、h10=+7、h16=+14） |
| v2 @3 次 | −82 | −86 | −71 | −83 | 平滑但仍不平整 |
| **v2 @4 次** | −80 | −86 | −70 | −83 | 平滑 |

根因：`step_fixed` **固定 2 次牛顿迭代**，方波/快速边沿下欠收敛 → 求解器进入**次谐波极限环**。
正弦输入下次谐波只有 −109 dB，**所以正弦测试完全发现不了**。

### 3.4 修复 + 重建

| 改动 | 内容 |
|---|---|
| 迭代次数成为网表指令 | `* @rustomp newton=<n>`，默认 2 → **3**；Sparklin Drive 用 **4** |
| 回归测试 | 方波次谐波必须 < −60 dB（实测 −70 dB） |
| 重建 | mono + stereo 重新构建安装（Legacy 不动） |

修复后数字：

| 指标 | 2 次迭代 | 4 次迭代 |
|---|---|---|
| 方波次谐波 | **+19 dB** | **−70 dB** |
| THD @0.2 V | 27.65 % | **27.58 %**（离线 27.579 / ngspice 27.5682） |
| 正弦谐波 vs legacy | 高次抬 2–4 dB | **逐次差 ≤1 dB** |
| 每内层样本 | ~1.0 µs | ~1.87 µs |
| 48k 单声道 / 立体声 | ~20 % / ~40 % | **~36 % / ~72 %** |

### 3.5 第二轮：浑浊消失，只剩极顶 2–4 dB

用户：**"浑浊声消失，整体音色已经非常接近"**。

补充的 1 kHz 方波截图显示：基频以下恢复干净，谐波阶梯平滑；
唯一剩余的系统性差异是 **9 kHz 以上新版低 2–4 dB**（与台架数据一致）。
这一条是**两种积分方法的真实差异**（legacy 梯形法的半样本延迟在极高次谐波上"多给"了一点），不是 bug。

### 3.6 顺带发现的第二个 bug：电位器拧到 100% 静音

用户报：**新版音量拉到 100% 没声，99% 正常。**

根因链：

```
level = 1  →  R_top = 500k·(1−1) = 0 Ω
           →  MNA 用导纳表示电阻，g = 1/0 = ∞
           →  矩阵 NaN（实测 20000/20000 样本非有限）
           →  引擎的 NaN 熔断复位并静音（**所以是"整块没声"**）
```

同一处还有 `gain = 0`（反馈电阻 = 0 Ω）→ 同样静音。

修复：框架在**唯一装配入口**把电阻夹到 `MIN_RESISTANCE = 1 mΩ`
（与"开关闭合 = 1 mΩ"同一约定），并加回归测试：8 个端点组合必须全部有限、音量随 level 单调。

## 4. 经验总结

### 4.1 测试信号要分层，正弦是最弱的一层

| 层 | 信号 | 能查出什么 | 查不出什么 |
|---|---|---|---|
| 1 | **正弦** | 稳态谐波结构、频响、失真量 | **求解器欠收敛**（2 次迭代时 THD 27.65 %、h2–h9 全对，却藏着 +19 dB 次谐波） |
| 2 | **方波 / 阶跃** | 收敛性、极限环、瞬态、带宽 | 真实乐器的掩蔽效应 |
| 3 | **真实乐器** | 整体的"味道"、可听性问题 | 具体是哪一项指标 |

> **验收必须三层都过。** 只用正弦 = 只验了一半。

### 4.2 把听感形容词翻译成指标

这次最有效的一步是把用户的描述映射到数字：

| 主观描述 | 客观对应 |
|---|---|
| "高频更毛更亮" | 高次谐波（10–18 kHz）**+2–4 dB** |
| "浑浊刺耳、数字味" | 基频以下**次谐波 +12~+19 dB**（电路里不存在的分量） |
| "正弦正常、方波露馅" | 收敛性问题只在快速边沿暴露 |
| "整体音色劣化" | 不是音色取向变了，而是**多了不该有的东西** |

**"多了不该有的东西"和"某个东西多了一点"是两类问题**：前者是 bug，后者是调音。

### 4.3 THD 通过 ≠ 算对了

- 2 次迭代的版本：THD 27.65 %（和 ngspice 差 0.09 pp）、h2–h9 逐次差 ≤0.03 pp —— **看起来完美**。
- 同一版本：方波下次谐波 +19 dB。

→ **验收指标里必须包含"不该出现的分量"**：次谐波、非谐波杂散、DC 漂移、NaN 计数。
只测"该有的对不对"，永远发现不了"多了不该有的"。

### 4.4 迭代次数是正确性参数，不是性能参数

- 固定迭代次数是为了实时确定性（不能"这一拍多迭代几次"），这是对的；
- 但**没有收敛判据时，"几次"就决定了结果对不对** —— 必须由**行为级回归测试**兜底
  （方波次谐波阈值），而不是靠"我觉得 2 次够了"。
- 代价可以量化接受：**用 2 倍 CPU 换回正确性**（单声道 20% → 36%）。

### 4.5 参数端点是 bug 的温床

凡是"由参数算出元件值"的地方，都要先问：

> **t = 0 和 t = 1 时，这个表达式等于几？**

这次的触发点是 `500k·(1−t)`：
- `t = 1` → 0 Ω（音量满档静音）
- `t = 0` → 0 Ω（反馈电阻为 0，整块静音）

而且**修复要放在最底层的单一入口**（MNA 的 `resistor()`），
不要在每一个生成表达式后面各自加 `max()` —— 模板里的公式会一直有人写错，包括写模板的人。

### 4.6 框架的"熔断"是止损，不是修复

引擎的 NaN 熔断把"NaN 扩散成整首歌都毁了"变成了"这块没声"。
**用户听到的"没声"正是熔断在工作** —— 熔断救了场，但问题还在。

→ 熔断必须有**配套的可观测性**：这次的诊断路径是
"没声 → 怀疑 NaN → 离线复现（数非有限值）→ 定位到 0 Ω → 夹紧"。
如果只有熔断而没有"数非有限值"的测试，这个 bug 会一直藏着。

### 4.7 AB 测试的工程前提

| 前提 | 做错的后果 |
|---|---|
| **身份隔离**（AU/VST3/CLAP id 都不同） | 后装的会覆盖前装的，AB 变成"自己比自己" |
| 参数位置一致 | 听感差异其实是增益差异 |
| 延迟一致 | 梳状滤波造成"厚薄/远近"错觉（这次两边都 15 样本，免检） |
| bypass 状态一致 | 一边干声一边湿声 |
| 修改后**重新构建并确认安装** | 听的是旧二进制（本次每次都核对 RMS / 时间戳） |

### 4.8 分析器只用来"看趋势"，数字要用台架

Logic 的 Channel EQ Analyzer 是**对数轴 + 时域平滑**，适合判断"有没有异常隆起/锯齿"，
不适合读绝对 dB。真正可引用的数字全部来自**可重复的离线台架**（同一段信号、同一窗长、可写成测试）。

→ 所以流程是：**分析器发现问题 → 台架量化 → 台架写成回归测试**。三步缺一不可。

### 4.9 助手这次预测错在哪（要记下来）

预测"新版高频只亮 0.5–1 dB"，实际是"高次谐波 +2–4 dB + 次谐波 +19 dB"。
错因：**只推演了"两种积分方法的线性差异"，没有把"定点迭代欠收敛"当成音色的一部分。**

→ 教训：**数值实现层本身就是音色的一部分。** 讨论"两条实现听起来是否一样"时，
必须把求解器（迭代次数、收敛判据、积分方法、状态初值）和器件模型放在同等地位上审视。

## 7. Rust FFT 复核（以数值为准，不再靠肉眼读分析器）

用户在 1 kHz 方波截图上怀疑"新版 9–10 kHz 有隆起、极低频有能量"。肉眼读对数轴分析器不可靠，
所以把整套测量搬进 Rust：**同一段信号 → 两边的完整 `Engine`（含 4× 过采样 + FIR）→ rustfft**。

### 7.1 方法

| 项 | 值 |
|---|---|
| 采样率 / 过采样 | 48 kHz 基带，`Engine` 内部 4× |
| 信号 | 1 kHz 正弦 / 1 kHz 方波，幅度 0.2 |
| 参数 | Gain = Level = 0.5，legacy 的 Clip Mode = Asym、bypass 关 |
| 采集 | 3 s 预热 + 1 s（48000 点 = 1000 个整周期）→ 矩形窗零泄漏，分辨率 1 Hz |
| 库 | `rustfft 6`（两个仓库各跑一次，输出 JSON 再合并） |
| 可复现 | 框架：`cargo run -p rustomp-dsp --release --example abfft`（用入库的 S1b 夹具）；legacy 仓库：同名 example |

### 7.2 结论先行

| 用户的怀疑 | 实测 | 判定 |
|---|---|---|
| 9–10 kHz 有隆起 | sine h9 = **−0.10 dB**、h10 = −0.14 dB；square h9 = **+0.22 dB**、h10 = **−5.0 dB**（v2 更低）；6–10 kHz 频段差 **+0.16 dB** | **不成立**（旧版 2 次迭代才有；现版最多 1/4 dB） |
| 极低频有能量 | LF 峰值（20–800 Hz）= **−103.74 dB**（v2）/ **−103.71 dB**（legacy） | **不成立**（两边完全一致，都是数值噪声底） |

### 7.3 正弦 1 kHz（0.2 V，Gain/Level 50%）

| | v2 | legacy | Δ |
|---|---|---|---|
| RMS | 0.35186 | 0.35214 | −0.007 dB |
| DC | −0.000101 | −0.000101 | — |
| THD | 28.264 % | 28.366 % | −0.10 pp |
| LF 峰值 | −103.48 dB | −103.43 dB | −0.05 dB |
| h3 / h5 / h7 | −12.97 / −18.46 / −22.33 | −12.96 / −18.43 / −22.27 | ≤0.06 dB |
| h9 / h11 / h13 | −25.45 / −28.16 / −30.62 | −25.35 / −28.01 / −30.40 | ≤0.22 dB |
| h17 / h19 / h21 | −35.48 / −38.88 / −43.99 | −35.09 / −38.39 / −43.36 | ≤0.63 dB |
| h22 / h23（22–23 kHz） | −54.45 / −51.60 | −53.45 / −50.52 | **−1.00 / −1.08 dB** |
| 10–16 kHz 频段 | −22.17 dB | −21.97 dB | −0.20 dB |
| 16–24 kHz 频段 | −29.85 dB | −29.38 dB | −0.47 dB |

→ **可听范围内（≤16 kHz）差 ≤0.5 dB；只有 22 kHz 以上到 −1 dB。**

### 7.4 方波 1 kHz（0.2 V，Gain/Level 50%）

| | v2 | legacy | Δ |
|---|---|---|---|
| RMS | 0.40242 | 0.40112 | +0.028 dB |
| THD | 45.351 % | 44.848 % | +0.50 pp（可由下面的奇次普遍 +0.2 dB 完全解释） |
| LF 峰值 | −103.74 dB | −103.71 dB | −0.03 dB |
| **奇次 h3…h21** | — | — | **+0.04 … +0.26 dB（系统性略高）** |
| 偶次 h6/h8/h10/h12/h14 | −42.1 / −46.1 / −51.0 / −59.3 / −66.8 | −40.7 / −43.3 / −46.0 / −49.3 / −54.4 | −1.4 … −12.4 dB |
| 偶次 h16/h18 | −56.3 / −53.0 | −68.5 / −57.2 | +12.2 / +4.2 dB |
| 0–100 Hz / 100–300 Hz 频段 | −64.95 / −97.24 | −64.90 / −97.20 | ≤0.05 dB |
| 6–10k / 10–16k / 16–24k 频段 | −12.73 / −14.72 / −19.24 | −12.89 / −14.94 / −19.43 | +0.16 / +0.22 / +0.19 dB |

三条要读懂的地方：

1. **奇次阶梯（决定音色的部分）逐次只差 0.04–0.26 dB**，方向一致（v2 略"利"一点点）。
   THD 的 +0.5 pp 全部来自这 0.2 dB（0.2 dB ≈ 2.3 % 幅度 ≈ THD +1.1 %，45.35 / 44.85 = 1.011 ✓）。
2. **偶次谐波的巨大相对差异是"数值地板"**：它们本身在 −42 ~ −68 dB，
   比相邻奇次低 **30–50 dB**，任何边沿处理的细微差别都会让它们相对变化几 dB —— 但绝对量听不见。
3. **没有任何基频以下的分量**（0–100 Hz 频段两边都是 −65 dB，LF 峰值 −103 dB）。

### 7.5 一句话

> **两版的差别全部 ≤0.5 dB（可听范围内），且集中在"最不利的位置"（偶次谐波、22 kHz 以上）。**
> 也就是说：**现在它们是同一台机器的两条数值路径**，剩下的差异已经不是"音色差异"，
> 而是"两种积分方法在小数点后一位的分歧"。

### 7.6 想自己复现"旧版的问题"

把插件网表里的 `* @rustomp newton=4` 改成 `2`，重新生成 + 构建，同样跑这两个例程：
方波的 f/8、f/16 会窜到 −10 dB 量级（LF 峰值从 −103 dB 升到 +10 dB 左右），
这正是当时截图里那片"极低频隆起"的来源。

## 8. 偶次谐波对比信号（可直接听）

§7 的结论里有一条很难"听出来验证"：**偶次谐波的相对差异有 1–12 dB，但绝对电平只有 −42…−68 dB**。
为了让人耳也能判断，把两侧输出**只保留偶次谐波**重建出来，做成 WAV。

### 8.1 复现

```bash
# 1) 两侧各自 dump 采集（1 kHz 方波，0.2 V，Gain/Level 50%，3 s 预热 + 1 s）
AB_DUMP_DIR=/tmp/abdump cargo run -p rustomp-dsp --release --example abfft
(cd ~/develop/sparklin-drive-legacy && AB_DUMP_DIR=/tmp/abdump \
   cargo run -p sparklin-drive-circuit --release --example abfft)

# 2) 重建 + 出 WAV
```

### 8.4 怎么听（关键实验在 swap 那一对）

1. **`swap_a_carrier_v2.wav` vs `swap_b_v2_with_legacy_even.wav`**：
   两条都是**原始电平**的全信号（RMS 都是 −7.91 dBFS），唯一的区别是"偶次谐波用谁的"。
   两者之差 **RMS −51.8 dBFS / 峰值 −39.2 dBFS**。
   **在正常监听音量下若听不出差别 → 偶次谐波差异在真实信号里不可听。**
2. `abex.wav`：一遍听完"偶次 A / 偶次 B / 差值"，注意第 3 段应当比前两段轻 12 dB。
3. `even_diff_boost.wav` 只用来"看内容"，它是被单独放大过的，不代表真实电平。

### 8.5 一个测量事故（必须记下来）

第一版 `even_abex.wav` 里，**差值段的音量与前两段接近** —— 用户当场指出。
检查文件峰值：三段都是 −1.0 dBFS —— **我对每一段各自做了峰值归一化**
（偶次 +30.8 dB、差值 +38.2 dB），把这个 12.3 dB 的真实差距**抹掉了**。

> **教训：要对比的两个信号，绝不能用各自的归一化增益。**
> 归一化会把你正要测量的东西（电平差）当作"要消除的差异"抹平 ——
> 这是测量里最典型的一类自欺：**别让工具替你做"听起来差不多"的判断。**

修正：`abex.wav` 改成**三段共用同一增益**；另外单独提供 `even_diff_boost.wav` 作为诊断，
并在文件名与文档里明确"哪个是原始电平、哪个是放大过"。

## 9. 后记：把 `newton` 从 4 提到 8

§8 之后用户追问"差值到底从哪来"。用**同一条带限方波**喂 ngspice 定案（`examples/abcmp_ngspice.rs`）：

| 指标 | 我们 4 次 | 我们 8 次 | ngspice |
|---|---|---|---|
| 方波基频 | 0.56508（+0.76 dB） | **0.51789（+0.0004 dB）** | 0.51784 |
| 偶次谐波逐次差 | 最大 14 dB | **≤2 dB** | 基准 |
| 偶次差值 RMS | −51.8 dBFS | **−64.4 dBFS** | — |
| 全带差值 RMS | −39.7 dBFS | **−45.0 dBFS** | — |

**结论：听到的偶次差异是"4 次牛顿迭代欠收敛"的残差，不是两种积分方法的模型差异。**
偶次谐波比奇次低 30–50 dB，同一份残差落在偶次上被放大成 ±10 dB —— 序列从"平滑衰减"变成"锯齿"。
提到 8 次后，与 ngspice 的基频差 0.0004 dB、偶次差 ≤2 dB。

**复现"锯齿"的方法**：把网表的 `newton=8` 改回 `4`，重新生成即可。

**代价**：48 kHz 下单声道 73%、立体声 146%。所以正式方案应是**自适应迭代**
（常态 4 次、残差大才补到 8 次）。
